# 改修の計画

「なし栞 + なしスタジオ」から分かれた **伺かスタジオ（Ukagaka Studio）** を、
大きく作りかえるための計画です。決まったことはここに書き足していきます。

---

## 変えないこと（前提）

改修しても、ここは守ります。どれも、元のプロジェクトのいちばんの持ち味です。

* **如何栞（`ikaga.dll`）は Windows 2000 から動く。** C ランタイムなしで組む形はそのまま。
  `node tools\check-imports.js` が見張ります。
* **ブロックを動かす規則は `shiori/src/interp.cpp` の 1 か所だけ。**
  画面の「ためす」も、同じものを exe に積んで使います。
* **伺かスタジオは exe 1 つで動く。** ランタイムのインストールなし、ポートを開かない、
  外への通信なし（SSP とだけ話す）。
* **画面をビルドする道具を増やさない。** `ui/` は書いたファイルがそのまま exe に入ります
  （Node や npm を入れなくても、`.\build.ps1` だけで作れる）。
* **テストが通らないものは入れない。** 1 つの段階ごとに `.\build.ps1 -Test` を緑にしてから先へ進みます。

## 進めかたの順番

3 つの狙い（内部の整理・UI の刷新・機能追加）は、**この順で**進めます。

```
段階 0  土台        フォークとしての身じたく
段階 1  内部の整理   画面のコードを分けなおす（UI を作りかえやすくするため）
段階 2  UI の刷新    見た目と画面の割りふりを作りかえる
段階 3  機能追加     新しいブロック・シェルまわり・SERIKO の残り
```

**整理を先にするのは**、いまの画面のコードが `app.js`（864 行）を中心に、
`window.IKAGA` という 1 つの入れものを通してつながっているためです。
このまま見た目を変えると、変えるたびに関係ないところが壊れます。
先に分けておけば、UI の刷新は「部品を差しかえる」作業になります。

機能追加の小さいもの（ブロック 1 つなど）は、段階 1・2 の途中に入れても構いません。

## 段階 1 — 内部の整理

### 1-1. 画面のコードを ES モジュールにする（済）

> 済ませたこと: `index.html` は `js/main.js` だけを読み、ほかは `import` でたどる形にしました。
> おたがいに import しあうところが残っていましたが、1-2 でなくしました。

いまは `index.html` に書いた順に読みこみ、各ファイルが `window.IKAGA` に自分のぶんを載せています
（**読みこみ順が依存の向き**という決まりで、`ui/test/modules.js` が守っています）。

これを、ブラウザが元から持っている **`import` / `export`（ES モジュール）** に変えます。

* ビルドの道具は増えません（WebView2 がそのまま読めます）。
* 「あとに読まれるものは、その場で引く」という決まりが要らなくなります。依存がファイルの先頭に書かれます。
* Node（v24）も ES モジュールをそのまま読めるので、テストも同じファイルを `import` するだけになります。
* exe の中から返すとき、`.js` の Content-Type を `text/javascript` にする必要があります
  （`studio/src/webview.cpp` / `assets.cpp` を確認）。

### 1-2. `app.js` を分ける（済）

`app.js` には、状態・再描画・メタ情報の欄・変数リスト・ズーム・右クリックメニュー・
「ためす」・お手本、が同居していました。次のように分けました。

```
ui/js/
├── main.js    組み立てだけ（各部品の init と、まとめて描きなおす）
├── shortcuts.js
├── panels/    右側の各タブ（実行・シェル・ゴースト・変数・検索とチェック・保存と書き出し・SSP）
├── editor/    描画・ドラッグ・パレット・かたまりの操作・ズーム・右クリック
├── core/      API 呼び出し・お知らせ・画面の状態（Session）・上の層への受け口（Commands）
└── model/     ブロックの定義・プロジェクトのデータと Undo・チェック・さくらスクリプトをほどく・ひな形
```

> 済ませたこと: import は上の層から下の層へだけ向き、**輪はひとつもありません**
> （`ui\test\modules.js` が層の向きと輪を見張ります）。下から上を呼ぶのは
> `core/commands.js` の 2 つ（`runScript` / `promptNewVariable`）だけです。
>
> 計画から変えたこと:
>
> * **`store.update(...)` は作りませんでした。** プロジェクトの中身・元にもどす・保存していない印は、
>   もともと `Model`（`Model.act` / `Model.onChange` / `Model.dirty`）が 1 か所で持っていたためです。
>   `App` にまざっていた「保存しない画面の状態」だけを `core/session.js` の `Session` に分けました。
> * **`blocks/` は作らず、`model/` に入れました。** どちらも DOM を触らない「データと規則」なので、
>   node のテストから同じように使えます。
>
> 残った宿題: 再描画はまだ `renderAll`（全部描きなおす）のままです。
> 段階 2 で画面を組みかえるときに、変わったところだけ描く形に寄せます。

### 1-3. スタジオ側（C++）の整理（済）

* `api.cpp`（655 行）は、`/api/...` の分岐が 1 つの関数に並んでいます。
  道すじごとの表（パス → 関数）にして、`project` / `ssp` / `export` / `shell` に分けます。
* `exporter.cpp`（771 行）は、descript・surfaces・バルーン・updates2.dau・nar を、
  それぞれのファイルに分けます。書き出しテスト（`studio/test/export.js`）がバイトで見張っているので、
  **中身を変えずに分ける**ことができます。

> 済ませたこと:
>
> * `api.cpp` は受け口の表（`kRoutes`）と共通の確かめ（よそのページからの要求を断る）だけにして、
>   中身を `api_project` / `api_shell` / `api_ghost`（ためす・記憶・記録）/ `api_export` / `api_ssp` に
>   分けました。計画の 4 つに、「ためす」と書き出したゴーストの記憶・記録をまとめた `api_ghost` を足しています。
> * `exporter.cpp` は、ファイル一覧の組み立てと書きこみだけにして、`export_program`（ghost.json）/
>   `export_shell`（仮の立ち絵・surfaces.txt）/ `export_seriko`（うごき）/ `export_balloon` /
>   `export_dau` に分けました。`exporter.h` の中身（ほかから使う関数）は変えていません。
> * 3 か所に同じ形で書いてあった「書き出すフォルダ名」を `GhostFolderName()` に、
>   2 か所にあった「パスのまわりの "…" を外す」を `Unquote()` にまとめました。
> * 書き出しテストはバイトのまま一致し、実際の exe で `/api/*` をひと通り呼んで答えを確かめました。

### 1-4. プロジェクトの形に版を持たせる（済）

`"format": "ikaga/1"` を、読みこむときに**ちゃんと見る**ようにします。

* `nashi/1`（元のなしスタジオのプロジェクト）も読めることを、テストで約束する。
* 形を変えるときは `ikaga/2` にして、`model.normalize` に「1 → 2 の直し」を足す。

> 済ませたこと: `Model.normalize` が最初に `format` を読み、`ikaga/1`・`nashi/1`・書いていないもの（版 1）を
> 開き、新しすぎる版と知らない形は理由つきで断ります。断ったときは、いま開いているプロジェクトを残します
> （起動時に前のプロジェクトが読めなければ、ひな形で始めて知らせます）。
> 「直し」は `model.js` の `MIGRATIONS`（版 n → n+1 の関数の表）に足す形にしました。まだ 1 つもありません。
> 決まりは `docs/ghost-json.md` の「format（形の版）」に、テストは `ui\test\editor.js` にあります。

### 2-1. 見た目の土台（済）

* 色・大きさ・角の丸み・影を **CSS 変数（デザイントークン）** にまとめる。
  いまの `style.css`（534 行）に直に書かれた値を置きかえます。
* **ダークモード**（Windows の設定に合わせる＋手で切りかえ）。
* ブロックの色をカテゴリごとに見なおし、色だけに頼らない（形やアイコンでも分かる）ようにします。

> 済ませたこと:
>
> * `style.css` の色を、`:root` の意味のある名前のトークン（`--bg` `--surface` `--text-muted` `--danger` …）に
>   まとめました。各トークンは `light-dark(明るいとき, 暗いとき)` で、両方の色を 1 か所に書いています。
>   直に書いてよいのは、ブロックの上に重ねる白と黒の半透明だけです（`ui\test\modules.js` が見張ります）。
> * **ダークモード**: ふだんは Windows の設定に合わせ、上のバーの ◐／☀／☾ のボタンで明るい・暗いに固定できます
>   （`core/theme.js`、この PC に覚えます）。ウィンドウのタイトルバーと、画面が出るまでの下地の色もそろえました。
> * ブロックの色・入力欄・ステージの吹き出しは、どちらの表示でも同じです（Scratch や SSP の見た目に合わせて）。
>
> 残したこと: **ブロックの色の見なおしと「色だけに頼らない」工夫**は、ブロックの見た目を組みかえる 2-2 で

### 2-2. 画面の割りふり（済）

いまは右側の細い列に、実行・ゴースト・変数・検索・チェック・書き出しの 6 タブが入っていて、
とくに「ゴースト」タブにメタ情報・設定・シェル・うごき・仮シェルの色がまとめて入っています。

案:

* **上に大きな切りかえ**: 「トーク（ブロック）」「キャラと絵（シェル・うごき）」「ゴースト情報」「書き出し」
* 右の列は、ブロックを組んでいる間に見たいもの（実行・変数・チェック・検索）だけにする
* うごき（SERIKO）は、こまを横に並べて見られる専用の画面にする

> 済ませたこと:
>
> * 上のバーのすぐ下に **トーク／キャラと絵／ゴースト情報／書き出し** の切りかえを置き、それぞれを 1 枚の画面にしました
>   （`panels/pages.js`）。トーク以外の画面は、カードを 2 列に並べた読みやすい形です。
> * トークの右の列は **ためす・変数・チェック・さがす** の 4 つだけにしました（7 から 4）。「▶ 実行」が 2 行に折れていたのも直りました。
> * **ヘルプ**は右上の **？** で開く画面にし、重なっていた「ショートカット」と「キーボード」の表を 1 つにまとめました。
> * **キャラと絵**: 立ち絵は大きな見本つきのカード、うごきは**こまを左から横にならべ**、こまごとに絵の見本を出します
>   （ほかのうごきを動かす・止めるこま、動く絵、絵の無い番号は、文字で分かるようにしました）。
> * `panels/shell.js`（505 行）を、画面に合わせて `chara.js`（キャラと絵）・`stage.js`（ためすのステージ）・
>   `surfaces.js`（立ち絵の絵を引く）に分けました。入力欄のつなぎかたは `fields.js` にまとめました。
> * **描きなおしは、いま見えている画面だけ**にしました（1-2 の宿題）。見えていない画面は、切りかえたときに描きます。
> * ほかの画面で Delete を押しても、見えないキャンバスのブロックは消えないようにしました。Ctrl+F はトークの画面にもどります。
> * **ブロックの色**: 色は Scratch のまま、**文字を黒に**しました（白だと黄色・オレンジで読みやすさの比が 1.7〜2.3。黒ならどの色でも 4.3 以上）。
>   比べた 3 つの案から選んでもらいました（「決めたこと」）。形と文字で意味が分かるので、色だけに頼る作りにはなっていません。
> * **お手本の重なり**: 新規のひな形・はじめて起動したときのサンプル・お手本 5 つのすべてで、かたまりが重なっていました。
>   **「整列」が、実際に描いた大きさを測って並べる**ようにし（いままでは幅を 420px と決めうちしていたので、長いかたまりが
>   となりの列にはみ出していました）、それでお手本を並べなおしました。列は、見えているキャンバスの高さで折りかえします。

### 2-3. つかいやすさ（済）

* はじめて開いた人むけの案内（お手本 → 動かす → 書き出す、までの道すじ）
* キーボードだけでブロックを置ける（検索して Enter で置く）
* 右クリックメニュー・ショートカットの一覧

> 済ませたこと:
>
> * **はじめてガイド**: はじめて起動したとき、トークの画面の右上に「お手本をひらく → ▶ で動かしてみる → SSP に入れて動かす」の
>   カードを出します。操作が済んだ手順から ✓ になり（順番どおりでなくてよい）、3 つとも済むか「もう出さない」で閉じます。
>   ヘルプの「はじめてガイドをもう一度」で、また出せます（`panels/guide.js`）。
>   「済んだ」の知らせは、新しい小さなしくみ `core/events.js` で受け取ります（`Events.emit('ran')` など。下の層から上の層へ知らせるもの）。
> * **キーボードだけでブロックを置く**: `/`（またはキャンバスの右下の「＋ ブロック」）で探す欄を開き、名前の一部を打って
>   Enter で置きます（`editor/picker.js`）。
>   * えらんでいるブロックのすぐ下に（帽子なら、かたまりのいちばん上に）つなげ、置いたブロックをえらんだ状態にします。
>     文字の欄があればそのまま打てて、Enter で決まります。`/` → 打つ → Enter をくりかえすだけで、下へ下へと組めます。
>   * えらんでいなければ、見えているところのあいた場所に新しいかたまりとして置きます。置くものの大きさを実際にはかり、
>     ほかのかたまりにも、ガイドや右下のボタンの下にも重ねません。空きが無ければその下に置いて、見えるところまで動かします。
>   * 「おわる」の下にはつなげない・丸いブロックは新しいかたまりにして入れかたを知らせる、などの形の決まりは守ります。
>     日本語の変換中の Enter では置きません。
>   * さがしかた（`model/blockindex.js`、`ui\test\editor.js` でテスト）: ひらがな・カタカナ・全角半角をそろえ、
>     ブロックの決まった字に出てくるものを、欄の既定値に出てくるものより先にします。同じならパレットの順です。
>     「話す」なら話すブロック、「改行」なら改行するブロックが先頭に来ます。中の名前（`say`・`OnBoot`）でもさがせます。
> * **えらんだブロックは、描きなおしてもえらんだまま**にしました（前は、何かを変えるたびに外れていました）。
> * **右クリックメニュー**: **何もないところ**にもメニューを出しました（ここにブロックを探して置く・ここにはりつけ・整列）。
>   ブロックのメニューには「コピー」「切り取り」「すぐ下にはりつけ」を足し、キーでできるものは右にキーを出します。
>   コピー・はりつけ・複製・削除は、メニューとキーで同じ処理を使います（`editor/clipboard.js`）。
> * **Ctrl+V** は、帽子をえらんでいるときも、かたまりのいちばん上にはりつけられるようにしました。
> * **? / F1** でつかいかたの画面を開きます。ヘルプのキーの表に `/`・`Esc`・`? / F1` を、右クリックのメニューの一覧を足しました。

### 2-4. 看板の差しかえ（ロゴ・マスコット）（済）

  目で確かめてから作りなおします。
* 栞のテスト用ゴースト（`shiori/test/`）の「なしこ」は、テストの材料なので変えません。

> 済ませたこと:
>
> * ロゴ `ui/img/logo.svg`（オレンジの吹き出し。上のふちにブロックのくぼみ、中に 2 行の文字）を描き、

>   梨のしゃれ「なしって おいしいよね」は、いかがのしゃれ「おちゃでも いかが？」にしました。
>   はじめて起動したときに置くファイルも `いかがちゃん.json` になります。
> * 「新規」と、名前が無いときの既定の名前を「あたらしいゴースト」にしました。書き出す readme.txt の
>   「ikaga 栞」も「如何栞」にしました。
> * 見つけて直したこと: **名前の欄を消して書き出すと、install.txt と descript.txt の `name,` が空になっていました**
>   （既定の名前は「項目が無いとき」しか効いていなかったため）。`GhostName()` で、空や空白だけのときも
>   既定の名前になるようにし、書き出しテストに名前の無いゴースト（`noname.json`）を足しました。
>   readme.txt の中身も、これで初めてテストに入りました。
>
> 計画から変えたこと: **マスコットの名前は「1 か所にまとめる」ことはしませんでした。** 名前はお手本の
> JSON（会話の中身の一部）にそのまま入っているためです。変えるときに書きかえるファイルの一覧を

### 2-5. 英語の画面（文書まで全部）

画面の作りかえと**一緒に**進めます。あとから文字を集めなおすより、作りかえるときに 1 か所へまとめるほうが早いためです。

* **しくみ**: 画面の文字を `ui/js/i18n/`（日本語・英語の辞書）にまとめ、`t('key')` で引く形にします。
  言語は Windows の表示言語に合わせ、設定で切りかえられるようにします。日本語を正とし、英語に無いものは日本語を出します。
  * ブロックの文（`%who が %text と話す`）は、言語ごとに語順を変えられるよう、ブロックごとに文を持ちます。
  * 辞書の抜けは、`check-blocks.js` と同じように node のテストで見つけます（英語に無い key・使っていない key）。
* **exe 側**: `/api/*` のエラーメッセージは、文ではなく**コード**（`project_not_found` など）を返し、
  画面が辞書で文にします。exe のメッセージボックス（閉じるときの確認・WebView2 が無いとき）は、exe の中で切りかえます。
* **書き出すもの**: ゴーストに入る `readme.txt` などは、書き出したときの画面の言語に合わせます。
  ゴーストの会話そのもの（お手本の中身）は、言語ごとにお手本を持つかどうかを、英語のお手本を作るときに決めます。
* **文書**: README と `docs/` に英語版を用意します（`README.en.md`、`docs/en/`）。日本語版を正とし、
  英語版の先頭に「日本語版が正です」と書きます。ライセンス（なしライセンス）は元の作者のものなので訳しません
  （英訳は LICENSE の中に元からあります）。
* 量の目安: 画面の文字およそ 760 か所（`blocks.js` 215・`index.html` 173・`shell.js` 85・`lint.js` 80 ほか）、
  exe のメッセージおよそ 60、文書およそ 1,500 行。
