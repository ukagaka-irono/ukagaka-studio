English: [README.en.md](README.en.md)（英語版。こちらの日本語版が正です）

[![build](https://github.com/ukagaka-irono/ukagaka-studio/actions/workflows/build.yml/badge.svg)](https://github.com/ukagaka-irono/ukagaka-studio/actions/workflows/build.yml)

伺か（SSP）のゴーストを **Scratch のようにブロックを積んで作れるアプリ** です。
組んだブロックは、伺かでよく使われている栞 **YAYA** の辞書に訳して書き出すので、
**書き出したものはふつうの YAYA ゴースト**です。YAYA で手書きしたゴーストに、ブロックで作ったトークを足すこともできます。
Windows ネイティブ（C++ / MSVC）で、ランタイムのインストールは要りません。

| | |
|---|---|
| **伺かスタジオ `ukagaka-studio.exe`** | ブロックエディタ本体（64bit・単体で動く1ファイル）。自前のウィンドウに WebView2 を埋め込んだネイティブアプリ。UI も YAYA 一式も exe の中 |
| **栞 YAYA `yaya.dll`** | 書き出すゴーストが使う栞（公式ビルドをそのまま。**SSP と同じく Windows 2000 から**動きます）。スタジオの「ためす」も、同じ `yaya.dll` で動かします |

## 動く環境

|  | |
|---|---|
| **書き出したゴースト**（`yaya.dll` が入ります） | **Windows 2000 以降**。SSP の動作環境に合わせてあります |
| **伺かスタジオ**（`ukagaka-studio.exe`） | **Windows 10 / 11**（WebView2 が要ります） |

ゴーストを**作る**のは新しい Windows で、**配ったゴーストが動く**のは古い Windows から、
という形です。エディタは WebView2（Edge）の上に乗っているので、古い Windows では動きません。

栞の `yaya.dll` は、そこに合わせるために **公式のビルドをそのまま**入れています。
いまの Visual Studio でソースから組むと、Vista からの API が混ざってしまい、
そこから下の Windows では**読みこみ自体が失敗する**ためです。
Windows 2000 にある API だけを使っているかは `node tools\check-imports.js` がいつでも確かめます
（くわしくは [`docs/maintenance.md`](docs/maintenance.md)）。

| どこから | 要るもの | 中身 |
|---|---|---|
| [**Releases**](https://github.com/ukagaka-irono/ukagaka-studio/releases) | 何も要りません | 版ごとの zip。**ふつうはこちら** |

Actions のほうは、実行ページをいちばん下まで送ると **Artifacts** の
`ukagaka-studio-<版>-<sha>` にあります。Releases の zip と同じ中身です
（exe / README（日本語・英語）/ CHANGELOG / LICENSE / docs / third_party（YAYA のライセンス））。

> Actions の成果物は、**GitHub にログインしていないと落とせません**（ボタンが出ません）。

どちらも**コード署名していない** ので、Windows に止められることがあります。
そのときは [スマートアプリコントロールでブロックされたら](#スマートアプリコントロールでブロックされたら) を見てください。

自分でビルドするなら `.\build.ps1` です（[`docs/maintenance.md`](docs/maintenance.md)）。

## つかいかた

### 1. 起動する

**`ukagaka-studio.exe` をダブルクリック** するだけです。
はじめてなら「開く」→「**お手本から始める**」で、動くゴーストを読みこんで
中を見るのがいちばん早いです（あいさつ／好感度／時間で変わる／名前をきく／ゴースト間通信）。
はじめて起動したときは、キャンバスの右上に **はじめてガイド**（お手本をひらく → ▶ で動かす → SSP に入れる）が出ます。
閉じたあとは、ヘルプ（右上の **？**）の「はじめてガイドをもう一度」でまた出せます。

* 自分のウィンドウが開きます。ブラウザは起動しませんし、アドレスバーもタブもありません。
* ウィンドウを閉じればアプリも終わります。保存していない変更があれば確認します。
* ウィンドウの位置と大きさは次回起動時に復元します。
* 二重起動しても増えません（すでに開いているウィンドウが前に出ます）。
* 保存していない変更があると、1 分ごとに自動で保存します。保存するたびに、上書きする前のものを**前の版**として残すので、
  「開く」でプロジェクトの 🕘 を押すと、前の版をえらんで開けます（開いたものを保存すると、それがいまの版になります）。
* 画面の言語は Windows の表示言語に合わせます。上のバーの **English**／**日本語** で切りかえられます
  （開いているものは、保存していない変更もそのまま残ります）。英語の画面では、お手本も英語のものが出ます。
* ゴーストが自分で言うこと（ブロックを置いていないイベントの反応）や「いまごろ」などの値の言語は、
  画面とは別に、**ゴースト情報の「ゴーストの言語」**で決めます（作りはじめたときの画面の言語になっています）。

**ポートは開きません。** 画面からの要求は WebView2 の中で受け取って、そのまま exe の中で処理しています。
外に出る通信もしません（SSP と話すときだけ `127.0.0.1:9801` へ接続します）。

> 画面表示に **Microsoft Edge WebView2 ランタイム**（Windows 11 標準搭載）を使います。
> 万一入っていない場合は、起動時に案内と配布ページへのリンクを出します。

### 2. ブロックを組む

画面は、上のバーのすぐ下で **トーク／セリフ／キャラと絵／ゴースト情報／書き出し** に切りかえます。
**セリフ** の画面には「話す」ブロックのセリフが一覧で出て、その場で直せます。CSV に書き出して表計算で直し、
読みこむと、変わったセリフだけを書きもどします。
ブロックを組むのは **トーク** の画面です。つかいかたとキーボードは、右上の **？** で開けます。

1. 左の **イベント** から「起動したとき」などをキャンバスにドラッグします。
2. その下に **セリフ** の「◯◯が □□ と話す」をつなげます。
3. 右の **ためす** タブの ▶ で、しゃべる様子とさくらスクリプトを確認できます。
   下に **いまの変数** が出ます。好感度などが変な値で固まったら「ここの変数をもどす」
   （エディタの中だけ）か「ゴーストの記憶を消す」（書き出したゴーストの `yaya_variable.cfg`）
   でやり直せます。ステージの**立ち絵をクリック・ダブルクリック・なでる**と、さわった場所（当たり判定）に応じた
   マウスのイベントを、SSP と同じえらびかたでためせます。
4. 立ち絵は **キャラと絵** の画面の「立ち絵」で、用意した PNG を番号ごとに割り当てられます
   （えらばなかった番号は、指定した色でかんたんな立ち絵を自動生成します）。
   立ち絵ごとの「**当たり判定**」で、絵の上をドラッグして、さわれる場所（あたま・かお…や、自分で付けた名前）を描けます。
   描くと、その立ち絵の自動の当たり判定のかわりになり、付けた名前はマウス系の帽子ブロックの場所えらびに出てきます。
   いまあるシェルのフォルダ（`shell\master` など）を「いまあるシェルのフォルダから読みこむ」に入れると、
   `surface0.png` のような番号の絵を、まとめてその番号に割り当てます。`surfaces.txt` の**うごき**（SERIKO/2.0 の書きかた）と
   **四角い当たり判定**、`descript.txt` の着せ替えの名前も読みこみます（四角でない当たり判定と、古い SERIKO/1 の書きかたは読みません。
   `surfaces.txt` で絵を組み合わせている番号は、1 枚の絵が無いので読みこめません）。
   同じ画面の「**うごき**」で、立ち絵をパラパラ切りかえるアニメーションを作れます
   （こまは左から順に、絵の見本つきでならびます）。
   「いつ動く」を決めておけば勝手に動きますし、「うごき N を再生する」ブロックでも呼べます。
   こまごとに重ねかたと位置を決められ、「そのうごきの間だけ触れる場所」も足せます。
5. **さがす** タブ（Ctrl+F）で、セリフや変数名からブロックを探せます。「置きかえる言葉」を入れて「すべて置きかえる」を押すと、
   ブロックの文字の欄（セリフ・選択肢など）の中をまとめて置きかえます（YAYA のコードの欄と変数の名前は置きかえません）。
   クリックするとその場所へ移動します。ブロックは **Ctrl+C / Ctrl+V** でコピーできます。
   コピーしたものは、別のプロジェクトを開いても、起動しなおしても、はりつけられます。ブロックが使っている変数が
   はりつけた先に無ければ、初期値つきで足します。
6. **チェック** タブに、空のセリフ・無い変数・行き先のない選択肢などが出ます。長すぎるセリフ・どこからもよばれないトーク・
   使っていない（値を入れるだけで読んでいない）変数も知らせます。
   赤い数字が付いていたら、そこを直してから書き出してください。項目をクリックすると
   その場所までキャンバスが動いて、ブロックが光ります。

**キーボードだけでも組めます。** **/** を押すと（キャンバスの右下の「＋ ブロック」でも）ブロックを探す欄が開くので、
「話す」「なで」のように名前の一部を打って **Enter** で置きます。えらんでいるブロックのすぐ下につながり、
置いたブロックの文字の欄にそのまま打てます。Enter で決めて、また **/** を押せば、下へ下へと組んでいけます。

**右クリック**すると、ブロックの上ならコピー・切り取り・はりつけ・複製・部品にする・無効にする・メモ・削除、
かたまりの帽子の上なら実行・複製・**たたむ**・メモ・部品にする・**YAYA を見る**・削除、何もないところなら「ここにブロックを探して置く」「ここにはりつけ」「整列」
「すべてたたむ」「すべてひろげる」が出ます。たたんだかたまりは、帽子と「◯ 個のブロック」の帯だけになります（帯を押すか、かたまりの上の ▸ でひろげます）。
キーの一覧は **?** か **F1** で開くつかいかたの画面にあります。

「**YAYA を見る**」は、そのかたまりが書き出すとどんな YAYA の関数になるかを、書き出すものとそのままの形で出します。
手で YAYA を書くほうへ移っていくときの見本になります。

**部品**は、よく使う組みかたに名前を付けて取っておくものです。ブロックの右クリックの「ここから下を部品にする」
（帽子なら「このかたまりを部品にする」）で保存すると、パレットの **部品** に並び、どのプロジェクトにもドラッグで置けます。
使っている変数が置いた先に無ければ、初期値つきで足します。部品の名前を変える・消すのは、パレットの部品の右クリックです。

**メモ**は、右クリックの「メモを付ける」で、ブロックやかたまりに書いておける覚え書きです。かたまりの右に付せんのように出て、
その場で書きなおせます（全部消すとメモも消えます）。動きには関係しません。書き出すと、YAYA の辞書の
そのブロックの前に `// メモ: …` のコメントとして入るので、手で YAYA を読むときの手がかりにもなります。
**さがす** タブでもメモの中をさがせます。

### 3. SSP に入れて動かす

**書き出し** の画面の「**SSP に入れて動かす**」を押すだけです。

* SSP の場所（`ssp.exe`）を自動で探します。動いていれば実行中のプロセスから、
  止まっていれば `C:\ssp` などのよくある場所から見つけます。
  見つからないときは、同じ画面の欄に `ssp.exe` のパスを入れて「この場所を使う」。
* SSP の `ghost\` フォルダへ直接書き出し、そのまま **SSP のゴーストを切り替えます**。
* すでにそのゴーストが動いていた場合は、書き出したあと **栞だけ読み込み直します**（切り替え無し・一瞬）。
* SSP が止まっていれば「SSP を起動」で立ち上げられます。
* 「**保存するたびに SSP に入れる**」を入れておくと、手で保存したとき（Ctrl+S など）に、SSP が動いていれば同じことをします
  （1 分ごとの自動保存では入れません）。直しては SSP で確かめる、をくりかえすときに便利です。

配布用にまとめるときは、同じ画面の「.nar を作る」。
できた `.nar` を SSP のウィンドウにドラッグ＆ドロップするとインストールできます。

> SSP で動いているゴーストに書き出し直すときは、下の「SSP に入れて動かす」を使ってください。
> 書き出したあと、栞に読みなおさせます（ふつうに書き出しただけでは、YAYA は読みなおしません）。

### 4. 動いているゴーストで試す（SSTP 連携）

**ためす** タブに SSP の接続状態が出ます。つながっていれば:

* **SSPでしゃべらせる** — いま選んでいるトークを、**デスクトップで動いている本物のゴースト**に
  しゃべらせます（エディタ内のプレビューではなく実機確認）。
* **イベント送信** — 選んでいるイベント（`OnMouseDoubleClick` など）を SSP に投げて、
  入れたゴーストが実際にどう反応するかを確かめます。
* **話しかけてみる** — 他のゴーストのふりをして、動いているゴーストに話しかけます。
  「話しかけられたとき」のブロックを選んでいれば、その相手・内容で話しかけるので、
  しぼり込みが効いているかそのまま確かめられます。

内部では SSP の **SSTP**（`127.0.0.1:9801`）に `SEND` / `NOTIFY` / `EXECUTE` /
`COMMUNICATE` を送っています。
SSP 側で「SSTP を受け付ける」設定が有効（既定でオン）になっている必要があります。

絵を用意していない場合は、簡単な立ち絵（サーフェス 0/1/2 と 10/11/12）を自動生成します。
自分で描いた絵に差し替えるときは `shell/master/` の PNG を置き換えてください。
既にあるシェル画像は、書き出し直しても上書きされません。

**バルーン（吹き出し）**も、**キャラと絵** の「バルーンも作る」を入れると同梱できます
（`balloon/` に PNG と `descript.txt` が入り、`install.txt` に置き場所が書かれます）。
入れないときは、使う人が持っているバルーンで表示されます。
色のほかに、かたち（角丸・四角・大きくまるい）・大きさ・しっぽの有無・線と文字の色もえらべます。
こちらも自分で描いた PNG があれば、書き出し直しても上書きしません。

### 5. ネットワーク更新に対応する

配ったあとのゴーストを、こちらの直したものに追いつかせるしくみです。

1. **ゴースト情報** の画面の「**更新のありか**」に、置き場所の URL を入れます
   （うしろに `/` を付けます。例: `https://example.com/ghost/ikagako/`）。
   ここが `descript.txt` の `homeurl` になります。空なら何も書かないので、更新もしません。
2. 書き出すと、フォルダに **`updates2.dau`**（中身の照合表）も一緒に作られます。
   使う人の SSP はこれを見て、**変わったファイルだけ**を落としてきます。
   自分で差し替えた絵やあとから足したファイルも、フォルダの中身から作るので入ります。
3. そのフォルダの中身を、URL の場所へ**まるごと**アップロードします。
   **必ずバイナリモード**で送ってください（テキストモードだと中身が変わって照合に失敗します）。
4. 使う人の側は、右クリックメニューの「ネットワーク更新」で新しくなります。
   ゴーストから始めたいときは「**ネットワーク更新をする**」ブロックを置きます。

> `updates2.dau` の形式は公式には公開されていません。伺かスタジオは、公開されている
> 読み取り側の実装（ninix-kagari の `lib/ninix/update.rb`）に合わせて書いています。
> `md5 miss` などでうまくいかないときは、**アップロードするフォルダを SSP のウィンドウに
> ドラッグ＆ドロップ**すると SSP が作り直してくれるので、それを上書きしてください。
> `.nar` の中には入れていません（アーカイブでは無くてもかまわないためです）。

更新のようすは `OnUpdateBegin` / `OnUpdateReady` / `OnUpdateComplete` / `OnUpdateFailure`
のイベントで受け取れます。ブロックを書かなくても、**更新できたとき**と**失敗したとき**は
栞が一言いいます（「変わりなし」と途中経過は黙っています）。

> 消したいファイルがあるときは、置き場所に `delete.txt` を用意します
> （ネットワーク更新は上書きだけで、消す操作はしないためです）。

### 6. 手書きの YAYA ゴーストにブロックを足す

YAYA で手書きしたゴースト（YAYA のテンプレートで作ったものなど）に、ブロックで作ったトークを足せます。

1. **書き出し** の画面の「手書きの YAYA ゴーストにつなぐ」に、ゴーストのフォルダ
   （`ghost\master` が中にあるフォルダ）を入れて **つなぐ** を押します。
   名前（`descript.txt` の name・sakura.name・kero.name）は、そのゴーストのものになります。
2. つないでいるあいだは、**書き出す**（または **SSP に入れて動かす**）と、そのゴーストに書きこみます。
   書くのは **スタジオのファイルだけ** です。
   * `ghost/master/studio_runtime.dic` と `studio_program.dic`（1 行目に `// ukagaka-studio: generated` の印）
   * `yaya.txt` の中の、`// ukagaka-studio: begin` から `// ukagaka-studio: end` までの数行（無ければ末尾に足します）

   手書きの辞書・`descript.txt`・シェル・`yaya.dll`・`yaya_base` には触りません。
   スタジオのファイルと同じ名前で、印の無いもの（人が書いたもの）があれば、上書きせずに止めます。
3. **同じイベントは手書きが優先** です。手書きの辞書にもあるイベント（たとえば `OnBoot`）は、
   スタジオは入り口を書きません（両方あると YAYA が辞書を読めず、ゴーストがだまるため）。
   ブロックも動かしたいときは、手書きの関数の中で `Studio.Event('OnBoot')` をよんでください。
   チェックタブが、そういうかたまりを知らせます。
4. ゴーストの `yaya.dll` と `yaya_base` はそのまま使います。古くてスタジオのしくみが動かないとき
   （YAYA 6 系でない・yaya_base を使っていない・古い）は、つなぐところに出して、書き出しを止めます。

ブロックの変数は、手書きの YAYA から `Studio.var['名前']` で読み書きできます。
反対に、ブロックから手書きの YAYA を使うときは、「**YAYA の関数 F を A B でよぶ**」（制御）と
「**YAYA の式 C の値**」（演算）のブロックを使います（関数の名前と式の欄には、ブロックをはめられません）。
つないでいるあいだは .nar は作りません。つなぐのをやめると、ふつうの書き出しにもどります。

### 保存される場所

`ukagaka-studio.exe` と同じフォルダに作られます。

| | |
|---|---|
| `projects\` | プロジェクト（作りかけのブロック）。初回起動時にサンプルが入ります（日本語なら `いかがちゃん.json`、英語なら `Ikaga.json`） |
| `projects\.history\` | プロジェクトの前の版。保存するたびに、上書きする前のものを残します（自動保存は 10 分おき・1 つのプロジェクトにつき新しいほうから 30 こ）。「開く」の 🕘 から開けます |
| `output\` | 書き出したゴースト（書き出し先を変えていない場合） |
| `parts.json` | 部品（よく使う組みかた。どのプロジェクトからも使います） |
| `ukagaka-studio.json` | 最後に開いたプロジェクト・書き出し先・ウィンドウの大きさ・言語 |
| `webview-data\` | WebView2 の作業フォルダ（消しても再生成されます） |

書き出すゴーストには、exe に埋めこんだ YAYA 一式（`yaya.dll`・`yaya_base`・`studio_runtime.dic`）が入ります。

## ビルド

Visual Studio の「C++ によるデスクトップ開発」が入っていれば、これだけです。

```powershell
.\build.ps1            # 32bit の手伝い（yaya_host.exe）→ スタジオ(64bit EXE)
.\build.ps1 -Test      # 画面を出さずに動かすコンソールも作り、テストも走らせる
.\build.ps1 -Release   # きれいに作り直してテストし、配布用の zip を作る
```

`-Release` は `dist\ukagaka-studio-<版>.zip` を作ります（中身は exe と読みもの）。
版の数字は **ルートの `VERSION` ファイル**の 1 行だけです。ここを直すと、
zip の名前と exe のプロパティ（右クリック→プロパティ→詳細）の両方に入ります。
変わったことは `CHANGELOG.md` に足してください。

`-Test` を付けると、9 つのテストが走ります。

| | |
|---|---|
| **そろい点検**（`tools\check-blocks.js`） | ブロックが「定義・YAYA への訳・説明（日本語と英語）・テスト」のすべてにそろっているか。ビルドが要らないので、いちばん先に走ります |
| **一致テスト**（`shiori\test\parity\parity.js`） | ブロックごとのかたまりを YAYA に訳して動かし、出てきたさくらスクリプトが決めておいた答え（`expected.json`）と同じか。同じかたまりを「ためす」と同じやりかた（`yaya_host.exe`）でも動かして、**「ためす」と SSP の答えが同じか**も見ます |
| **ふるまいテスト**（`shiori\test\behavior\behavior.js`） | しくみの辞書が持っている判断 — 同じイベントに複数あるときどれを選ぶか、ブロックが無いときの既定の反応（英語のゴーストなら英語で）、`OnClose` の `\-`、「◯秒ごと」の間引き、ランダムトーク、なでなでの生成、通信の届け先、SAORI（テスト用のおそい DLL を実際に呼びます） — が期待どおりか |
| **YAYA のテスト**（`shiori\test\yaya\yaya.js`） | YAYA（`third_party\yaya\`）が公式のビルドのままで動くか。変数が次の起動に残るか、exe の書き出しがそのまま YAYA で動くか、手書きの YAYA ゴーストにつないで書き出しても手書きのファイルがバイトのまま変わらないか |
| **書き出しテスト**（`studio\test\export.js`） | 書き出したファイル（`surfaces.txt` / `descript.txt` / `ghost.json` / `install.txt` / `yaya.txt` / `studio_program.dic` とファイルの一覧）の中身が期待どおりか。`updates2.dau` は MD5 を node の `crypto` と突き合わせます |
| **エディタテスト**（`ui\test\editor.js`） | 読みこんだプロジェクトの整形と形の版の確かめ（`model.js`）と、チェックタブが出す注意（`lint.js`）、ブロックを字でさがすところが期待どおりか。お手本がどれもチェックに引っかからないか。ヘルプの「このソフトについて」の表示が README・LICENSE と同じ文か |
| **輸入の点検**（`tools\check-imports.js`） | 書き出すゴーストに入れる `yaya.dll` の輸入表を直に読んで、**Windows 2000 に無い API** が混ざっていないか。混ざると、そこから下の Windows では DLL の読みこみ自体が失敗します（版を上げたときのため） |
| **画面ファイルの点検**（`ui\test\modules.js`） | `ui\js\*.js`（ES モジュール）が入り口の `main.js` からたどれるか、どれを最初に読みこんでも落ちないか、`Xxx.yyy()` の呼び先がそろっているか。ファイルを分けたときの**移し忘れ**を捕まえます。`style.css` の色がトークンを通っているか（暗い表示で色がぬけないように）も見ます |
| **画面の言葉の点検**（`ui\test\i18n.js`） | 画面の日本語がすべて `t()` を通り、英語の訳があるか（英語の画面でそこだけ日本語が残らないように）、英語の辞書に古い訳や `{差しこみ}` のずれが無いか、exe が返すエラーのコードがすべて画面の文になるか。文書の英語版がそろっているか |

この 9 つだけ **Node.js**（22.12 以降）を使います（入っていなければ飛ばします。アプリの動作には要りません）。
ふるまいテストには、わざと待つ場面（おそい SAORI と終了が重なるところ）があるので、
10 秒ほどかかります。
ブロックやふるまいを足したら、`shiori\test\` `studio\test\` `ui\test\` の材料と期待値も
いっしょに直してください。書き出しかたや、ブロックの出すものをわざと変えたときは、出てきたものを目で確かめてから
`node studio\test\export.js --update` / `node shiori\test\parity\parity.js --update` で期待値を作りなおします。

**ブロックを 1 つ足すときの手順**（どのファイルに何を書くか）と、つまずきやすいところは
[`docs/maintenance.md`](docs/maintenance.md) にまとめてあります。

この 9 つは **GitHub でも自動で走ります**（`main` への push・`v*` タグ・プルリク）。
打ち忘れても止まるようにするためのものです。設定は `.github/workflows/build.yml`。

個別に作るときは `shiori\build.ps1`（32bit の手伝いとテスト用のコンソール）/ `studio\build.ps1`。
スタジオのビルドでは `studio\tools\embed.ps1` が `ui\` 以下と YAYA 一式（`yaya.dll`・`yaya_host.exe`・
しくみの辞書・`yaya_base`）をリソースにまとめ、exe に埋め込みます（UI や辞書を直したら再ビルドしてください）。

栞 **YAYA** の公式ビルド（`yaya.dll`）と、その受け口の辞書 `yaya_base` は `third_party\` に入れてあります。
ソースからは組みません（いまの Visual Studio で組むと Windows 2000 で動かなくなるため）。どこから持ってきたか・版の上げかたは
[`third_party/README.md`](third_party/README.md) にあります。YAYA のライセンス（AYA Ver.5 の条件／BSD 3-Clause）の
本文は `third_party\yaya\` にあり、配布用の zip にも入ります。

WebView2 の SDK は `studio\third_party\webview2\` に入れてあります（ヘッダと静的リンク用の
`WebView2LoaderStatic.lib` だけ。**BSD 3-Clause**）。ダウンロードは不要です。
exe に静的リンクしているので、**配るときは著作権表示の同梱が要ります**。
その本文はルートの [`LICENSE`](LICENSE) の後ろに入れてあり、配布用の zip にも入ります。

### スマートアプリコントロールでブロックされたら

Windows 11 の **スマートアプリコントロール**（既定でオンの環境があります）は、
署名がなく実績のない exe をブロックすることがあります。ビルドしたばかりの
`ukagaka-studio.exe` が「アプリケーション制御ポリシーによってブロックされました」と
言われた場合は、次のどれかで対応してください。

1. **少し待ってもう一度実行する** — 判定が確定すると通ることがあります（確実ではありません）。
2. **コード署名する** — 公的な認証局のコード署名証明書があれば確実です。
   ```powershell
   .\studio\build.ps1 -SignThumbprint <証明書の拇印>
   ```
   自己署名証明書ではスマートアプリコントロールの信頼は得られません。
3. **スマートアプリコントロールを切る** — Windows セキュリティ →「アプリとブラウザーの制御」→
   「スマートアプリコントロール」→ オフ。
   **一度オフにすると Windows を再インストールするまで戻せません**。よく考えてから行ってください。

作りたての `yaya_host.exe` や `test_host.exe` が、テストの途中で同じように止められることも
あります（`error 4551`）。**もう一度ビルドすると通る**ことが多いです。

## 栞のしくみ

書き出したゴーストの `ghost/master/` には、次のものが入ります。

| | |
|---|---|
| `yaya.dll` | 栞 YAYA（公式ビルド）。`descript.txt` の `shiori` がこれを指します |
| `yaya.txt` | YAYA の設定。どの辞書を読むかが書いてあります |
| `yaya_base\` | YAYA のシステム辞書（SHIORI/3.0 の受け答えをして、イベントの名前の関数をよぶ） |
| `studio_runtime.dic` | **しくみの辞書**。どのかたまりを選ぶか・間引き・既定の反応などの決まった部分（どのゴーストでも同じ） |
| `studio_program.dic` | **ブロックを訳した辞書**。かたまり 1 つが YAYA の関数 1 つになります |
| `ghost.json` | ブロックの写し。YAYA は読みません（「読み込み」でプロジェクトとして開けるように置いています） |

スタジオが書く 2 つの辞書は、1 行目の `// ukagaka-studio: generated` で見分けます。書き出すたびに上書きするので、
手で YAYA を書くときは、べつの辞書ファイルに書いて `yaya.txt` に足してください。

* SSP から来たイベント（`OnBoot`、`OnMouseDoubleClick` など）は、`yaya_base` がイベントの名前の関数をよび、
  `studio_program.dic` のその関数が、しくみの辞書に「このイベントのかたまりを動かして」と頼みます。
  出てきたさくらスクリプトが `Value:` で返ります。
* 同じイベントのスクリプトが複数あるときは、`weight`（えらばれやすさ）で抽選します。
  直前に選んだものは避けます。しぼり込みを書いたブロックは、条件なしの同じイベントより**優先**されます。
* `OnSecondChange` を数えて、設定した間隔で **ランダムトーク**（`kind: "talk"`）を再生します。
  直近に出したトークは候補から外すので、同じ話が続きません（外す数はゴーストの設定で変えられます。
  既定はトーク数の半分・最大 8）。そのあいだ、`yaya_base` のランダムトーク（`aitalkinterval`）は止めます。
* 変数・起動回数・出したトークの順番は、YAYA の保存のしくみで **`yaya_variable.cfg`** に残り、次の起動で続きから使えます。
  ブロックの変数は **`Studio.var['名前']`** の 1 つの入れものにまとめてあるので、どんな名前でもそのまま使え、
  手書きの YAYA の変数ともぶつかりません。
* イベントは大きく **はじめの1回**（`OnFirstBoot` / `OnBoot`）・**定常ループ**（`OnSecondChange`）・
  **その他のイベント**の 3 つに分かれます。定常ループは SSP が毎秒たたいてくるので、
  帽子ブロックの「◯秒ごと」で間引けます（`everySec`）。
* マウス系のイベントは、**当たった場所（あたま・かお・むね・スカート・て）と相手**で
  しぼり込めます。書き出す仮シェルにも、その名前の当たり判定を入れてあります（「キャラと絵」で描きかえられます）。
* `OnMouseMove` が同じ場所で続いたら **`OnNadeNade`（なでられたとき）** を自分で作ります。
  SSP にはこのイベントはありません。しくみの辞書の中で数えています。
* **ゴースト間通信**（`OnCommunicate`）に対応しています。相手の名前と言われたことで
  しぼり込めます。こちらから話しかけるときは応答に `Reference0: 相手の名前` を付けます。
  話しかけ合いが 8 往復続いたら、しゃべるだけにして通信は打ち切ります。
* **外部モジュール（SAORI）** は、YAYA の `REQUESTLIB` でよびます（答えが返るまで待ちます）。
  「答えを待たずによぶ」ブロックも、中では答えを待ってから、つぎの `OnSecondChange` で `OnSaoriDone` を作って知らせます。
  YAYA には別のスレッドで動かすしくみが無いので、時間のかかる SAORI のあいだはゴーストが止まります。
* ブロックが未定義のイベントには、あいさつなどの控えめな既定動作を返します
  （ゴーストの言語が英語なら英語で）。
  `OnClose` では必ず `\-` を付けて、ゴーストがちゃんと終了するようにします。
* 記録（`studio_debug.txt`）は、そのファイルがあるときだけ書きます（「ためす」の「記録をはじめる」で作ります）。
  読みこんだこと・YAYA の注意・SAORI を読みこめないことなどが残ります。

エディタの「ためす」も、SSP に入るのと同じ 32bit の `yaya.dll` が動かしています。画面はブロックを YAYA の辞書に訳して
`POST /api/preview` で頼み、伺かスタジオは exe に埋めこんだ 32bit の手伝い `yaya_host.exe` で、それを動かします
（画面側にブロックの解釈はありません）。違うのは 2 つだけで、**SAORI は呼びません**（ゴーストのフォルダの DLL が無いため）、
**起動してからの時間や起動回数などは画面から渡します**。「ためす」と SSP で同じ答えになることは、一致テストが確かめています。

> 1.x までは、自前の栞 **如何栞**（`ikaga.dll`）がブロックを動かしていました。2.0 で YAYA に置きかえ、
> 動きは如何栞と同じになるように作ってあります。わざと、または YAYA ではできないために同じにならないところは、
> [`docs/roadmap.md`](docs/roadmap.md) の 3-3 にあります。
> 前に如何栞で書き出したゴーストも、プロジェクトを開いて書き出しなおせば YAYA のゴーストになります
> （如何栞の変数の保存 `ikaga_save.json` は引きつぎません。変数はプロジェクトの初期値から始まります）。

### SSP なしで試す

```powershell
.\build.ps1 -Test
.\shiori\dist\test_host.exe .\output\いかがちゃん\ghost\master OnBoot OnMouseDoubleClick:0,0,0,0,Head OnClose
```

`test_host.exe` は SSP のかわりに、フォルダの `yaya.dll` を読みこんでイベントを順にたずねます
（ほかの栞の DLL を試すときは `--dll <名前>`）。`イベント名:参照0,参照1,...` の形で指定します。`OnSecondChange:0,1*200` のように `*回数` を付けると繰り返せます。
`!sleep:300` を挟むと、その場で 300 ミリ秒待ちます（答えを待たない SAORI のように、
裏で動いているものが終わるのを待つとき用）。

## つくれるもの / まだできないこと

できること:

* セリフ、表情（サーフェス）切り替え、間（ウェイト）、クリック待ち、バルーン切り替え
* 選択肢（`\q`）とその行き先、リンク（`\_a`）、音（`\_v`）
* 変数（好感度・フラグなど）、条件分岐、くりかえし、ランダム分岐、トークの呼び出し
* ゴースト間通信（`OnCommunicate`）— 話しかけられたときの反応と、こちらから話しかけること
* **SSP の右クリックメニューに項目を足す** —「◯◯ を SSP のメニューからえらばれたとき」の帽子ブロック。
  書き出すと、SSP の右クリックメニューの「おすすめ」に、その名前の項目が出ます（えらぶと、その帽子の下が動きます）
* 3 人目以降のキャラ（`\p[n]`）の切りかえ
* 外部モジュール（**SAORI**）の呼び出し — ゴーストのフォルダに置いた 32bit の DLL
  （「答えを待たずによぶ」ブロックもありますが、YAYA では答えを待つので、そのあいだゴーストは止まります）
* **手書きの YAYA ゴーストにブロックを足す**、ブロックから**手書きの YAYA の関数や式を使う**
* **うごき**（SERIKO のアニメーション）— 立ち絵をパラパラ切りかえる。キャラと絵の画面で作る
  （こまごとに位置ずらし・重ねかた（`interpolate` や `blend-*` など）を選べます。
  ほかのうごきを動かす／止める（いくつかのうちどれか・まとめて も）、大きさを変える、APNG を差しこむ、
  そのうごきの間だけ触れる当たり判定（四角・だ円・丸・多角形）を足す、もできます）
* **着せ替え**（MAYUNA）— 部品をうごきとして作り、SSP の着せ替えメニューや「着せ替え」ブロックで着る／ぬぐ
* **ネットワーク更新**（`homeurl`・`updates2.dau` の書き出し・更新のイベント・更新のブロック）
* **たずねる**（入力ボックス）— 使う人が書いた文字を、そのまま変数に入れる
* **N 秒後によぶ**（かんたんな予約）、**イベントを自分で起こす**、
  **交代する** / **ブラウザで開く**
* 仮のシェル（立ち絵）と、**バルーン（吹き出し）**の自動生成
* 時刻・曜日・起動回数・**いまごろ（朝昼夕夜）・季節**などの情報、四則演算・比較・文字列操作
* ランダムトークの**まとまり**（朝のトーク、季節のトーク…）と、そこから 1 つよぶブロック
* どうしても必要なときの「さくらスクリプトをそのまま出す」ブロック

まだできないことは、いまのところ挙がっていません。足したいものがあれば、[`docs/maintenance.md`](docs/maintenance.md) の
「ブロックを 1 つ足す」を見てください。

## 安全のはなし

* **ポートは開きません。** 画面からの要求は WebView2 の中で受け取り、そのまま exe の中で
  処理しています。外に出る通信は、SSP と話すときの `127.0.0.1:9801` だけです。
* 画面は `https://ikaga.example/` という**見せかけのアドレス**で動いていて、
  そこから外のページへは移動しません（移動しようとしたら、既定のブラウザに渡します）。
  外部リンクを開くときも `http` / `https` だけを渡します。
* exe の中の API は、**画面自身から出た要求だけ**を受け付けます
  （独自ヘッダか、同じアドレスから来たことの確認）。
* しくみの辞書は、**外から来た文字**（他のゴーストに言われたこと、入力ボックスに書かれたもの）を
  さくらスクリプトに入れるとき、タグを閉じる `[` `]` と改行を落とします。
  ただし `さくらスクリプトをそのまま出す` ブロックは素通しなので、そこに外から来た文字を
  入れないでください。
* **人からもらったプロジェクト（.json）は、開く前に中身を確かめてください。**
  立ち絵の画像はパスで指定されているので、書き出すとその画像がゴーストに同梱されます。
  知らないパスが入っていたら、キャラと絵の画面の「立ち絵」で外せます。
* ブロックから読む SAORI の DLL は、ゴーストのフォルダの中だけです
  （`..` や絶対パスは、しくみの辞書が断ります）。
* SAORI は答えが返るまで待ってよぶので、終わらない SAORI をよぶとゴーストが止まります。
  信用できる DLL だけを使ってください。
* 「YAYA の関数 F を A B でよぶ」「YAYA の式 C の値」のブロックは、関数の名前と式の欄に**ブロックをはめられません**
  （ほかのゴーストから来た言葉などを、YAYA のコードとして動かさないため）。
* 変数 1 つに入れておける長さは 32000 文字までです（つなげ続けてメモリを使いきらないため）。
  1 回に出すさくらスクリプトも 32000 文字までで、こえたぶんは出しません。

## メモ

* 生成される仮シェルは、絵を用意するまでの繋ぎです。配布するゴーストには自分の絵を使ってください。
* PNG も .nar も外部ライブラリを使わず自前で書き出しています（zlib 不要）。

  見せかけのアドレスから exe の中身を直接返しているだけで、通信はしていません。

  「ためす」は動きません（どれも exe の中の処理を呼んでいるためです）。
